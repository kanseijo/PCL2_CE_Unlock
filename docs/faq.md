# FAQ / 常见疑问

## Q1「注入版」到底算不算"修改启动器"？

要分两层看，混在一起就容易吵起来：

| 层面 | 注入版 | 补丁版 |
| --- | --- | --- |
| **文件层面** | ✅ **一个字节都不改**：exe 的 SHA256 不变，官方 Sigstore 签名仍可验证 | ❌ 改动 204 字节，哈希变化 |
| **行为层面** | ✅ 也**确实改变了**：进程内 5 个方法的返回值被替换（这才是解锁生效的原因） | ❌ 同样改变（直接改 IL） |

所以准确说法是：

- ✅ **"不修改启动器文件"** —— 成立，可验证（哈希/sigstore）。这是我们说"可逆、签名不受影响"的依据。
- ❌ **"不修改启动器"** —— 不成立。运行时行为被你改了，只是**没有落盘**。

一句话：**注入版是"临时改变行为、不改文件"；补丁版是"永久改变行为，同时改文件"。**

## Q2 为什么注入版关掉启动器后，限制又回来了？

因为**所有改动都在进程内存里**，进程退出即消失：

- 注入通过环境变量 `DOTNET_STARTUP_HOOKS` 让 .NET 在 `Main` 之前加载 `hook/PCL2_CE_Unlock.Hook.dll`；
- Hook 用 MonoMod 在内存中替换目标方法入口（detour），**从不写回磁盘**；
- 关掉进程 → 内存没了 → 下次**直接双击官方 exe** 就是**完全原版行为**，限制依旧。

这不是缺陷，而是"不改文件"必然的代价：

| 特性 | 注入版 | 补丁版 |
| --- | --- | --- |
| 必须通过工具/快捷方式启动 | ✅ 必须 | ❌ 双击官方 exe 即可 |
| 官方文件哈希/签名 | 不变（可验证） | 变了 |
| 上游自动更新 | 安全（换 exe 后钩子照旧生效） | 会被覆盖，需重打 |
| 是否落盘 | 否 | 是（带 `.原版.bak` 备份，可一键还原） |

## Q3 那我该选哪个？

| 你的情况 | 建议 |
| --- | --- |
| 想双击就能用、不介意改文件（有备份可还原） | **补丁版**（菜单 `3)`） |
| 在意官方签名/哈希不变、或者经常跟着官方更新 | **注入版**（菜单 `4)`，或桌面快捷方式） |
| 只是想验证工具做了什么、随时可回退 | **注入版** |

两种形态共用**同一份解锁定义**（`src/Shared/UnlockTargets.cs`），解锁范围完全一致。

## Q4 会不会影响正版登录 / 被检测？

- 微软正版登录**完全不影响**：OAuth ClientId 是编译期常量，补丁/Hook 都没有碰登录链路；
- 保留正版劝导：`McLaunchPrecheck` 与 `HasMicrosoftProfile` **逐字节未改动**，打补丁时会自动校验；
- 不涉及游戏鉴权：离线登录是 PCL 自带的 `PageLoginOffline`，本项目只是放开了入口限制。

## Q5 为什么要做两种形态？

因为两者各有硬性取舍（见 Q2 表格），没有一种能同时满足"零改动"和"双击即用"。
把选择权交给使用者，比只给一种更实用。
